## 1. 已确认的产品边界

- 一个 PHP 环境对应一个 PHP 运行容器、一套 PHP 配置和扩展，可被多个项目绑定。
- 不为项目建立独立 FPM pool；PHP-FPM 使用环境自身的统一配置。
- 相同 PHP 版本允许创建多个不同配置的环境，以稳定的环境 ID 区分，名称可修改。
- 项目切换选择环境，不直接修改共享环境的 PHP 版本、扩展或配置。
- 创建目标环境时，扩展由 install-php-extensions 按目标 PHP 选择兼容版本；不复制旧扩展二进制。
- 切换不检查 composer.json 或 composer.lock 的 PHP、扩展要求，不执行 Composer，也不修改依赖文件或 vendor。
- 已就绪环境间切换不重建 PHP 容器、不重建镜像；目标环境未启动时执行“启动并切换”。
- 环境构建、配置变更、扩展变更仍可能需要重载或重建环境，操作前展示所有受影响项目。
- 已有独立项目保持原运行方式，通过显式迁移接入共享环境。

## 3. 存储与执行模型

### 环境

建议存储在 `~/php-dev/environments/<environment-id>/`，与项目目录分开：

- `environment.json`：ID、名称、目标 PHP 版本、扩展声明、构建代理设置。
- `Dockerfile`、`docker-compose.yml`、PHP 配置、启动脚本和环境日志。
- 容器、镜像和网络别名使用稳定 ID，重命名环境不改变资源身份。
- 显示版本和扩展来自容器实际探测，区分“配置版本”与“实际运行版本”。

### 项目

- 在项目管理目录的 `.phpbox/project.json` 保存稳定项目 ID、环境 ID、项目启停意图。
- 原有代码、Nginx、数据库数据卷和任务文件保持项目所有；环境不拥有这些数据。
- 未迁移项目仍是独立运行模式，不生成假的项目 PHP 服务来兼容旧调用。
- 指定环境不存在时显示绑定错误，不自动选择另一个环境运行。
- 环境引用项目列表通过项目绑定计算，避免维护两份引用计数。

### 路径与网络

- 环境统一挂载项目根目录到 `/workspaces`，新增项目无需修改现有环境的挂载。
- 项目代码路径按真实结构解析，例如 `/workspaces/demo/demo`；已有 `src` 结构也按实际路径处理。
- 项目 Nginx 只挂载该项目所需目录，代码在 Nginx 与 PHP 中使用相同绝对路径。
- 检查上传、缓存、日志写入权限；CLI 默认采用宿主用户 UID/GID，沿用任务已选执行用户。
- 建立 PHPBox 管理的共享 Docker 网络，用稳定环境别名访问 FPM；不把 FPM 端口发布到宿主机。
- 项目数据库通过唯一项目别名连接，例如 `db-<project-id>`、`redis-<project-id>`。不依赖共享网络上可能重名的 `mysql`、`redis` 服务名。
- 迁移预览必须列出数据库地址及绝对路径变化；只更新 PHPBox 管理的配置，应用自己的 .env、硬编码路径需要用户确认和调整。
- Nginx 对环境地址使用 Docker DNS 动态解析，环境重建后不能继续连接失效 IP；需要验证启动、重建和重启场景。
- 共享环境会看到挂载项目目录并共享资源、进程权限和 PHP 配置，面向同一用户的可信本地项目，不提供租户隔离承诺。

## 4. 环境管理与界面

新增“PHP 环境”页面：

- 显示名称、实际 PHP 版本、状态、扩展、绑定项目。
- 支持创建、重命名、启动、停止、配置、安装扩展、重建和删除。
- 创建时选择 PHP 版本、扩展和构建代理；复用已有后台操作、取消及重新打开窗口能力。
- 有项目绑定的环境不能删除；停止或修改环境前展示影响项目。
- 环境的 PHP 版本在创建时确定；需要其他版本时新建环境并切换项目。
- 构建代理与运行环境分开，保留已有阻止 Docker 客户端注入回环代理的处理。

项目页面：

- 显示“使用环境：名称 · PHP 版本”，提供“切换环境”和“管理此环境”。
- PHP 配置、扩展和重建入口操作共享环境，不能伪装成项目独享配置。
- PHP 引擎日志标注为共享环境日志；Nginx、应用及任务日志保留项目归属。
- 项目停止时不能因为共享 PHP 正在运行就显示“部分运行”。环境异常则使依赖它的运行项目显示依赖异常。

切换弹窗：

- 当前环境、目标环境选择、新建环境入口。
- 展示 PHP 版本、扩展和主要配置差异。
- “检查环境”按钮；提交时重新执行必要检查。
- 已停止目标环境显示“启动并切换”；当前绑定环境不可重复提交。
- 不加入“保留原 PHP 配置”“只切网站”“自动升级依赖”等选项。

## 5. 切换流程与失败恢复

1. 获取项目操作锁，阻止同项目的切换、删除、重命名及启动操作并发冲突。
2. 解析目标环境、代码路径、项目服务和调度状态；构建中、异常或即将删除的目标不可选。
3. 启动未运行的目标环境，验证 PHP-FPM、实际版本、代码可见性和文件权限。
4. 不读取或校验 Composer 平台要求，不因项目声明的 PHP 或扩展要求阻止切换。
5. 展示源/目标扩展差异，不把源环境全部已安装扩展都视为项目必需，也不自动更改目标环境。
6. 保存原绑定和受管理配置，写入切换阶段记录。阻止新 PHPBox 命令和调度在切换窗口内启动，已有执行继续留在原环境。
7. 更新该项目的 Nginx 上游，先执行配置检查，再平滑重载；停止状态的项目只保存配置，保持停止。
8. 提交新绑定，更新两个环境的项目调度记录；执行版本及路由探测后结束切换。
9. 失败时恢复原绑定、Nginx 配置和调度。回滚失败明确标记“需要处理”，保留日志；不清理共享容器、镜像或数据库数据卷。

补充约束：

- 只对受管理的路由片段执行替换，不覆盖整个自定义 Nginx 配置。
- 只读检查不能证明业务完全兼容；不自动以业务首页请求作为成功依据，避免触发业务操作。
- 切换阶段记录用于进程异常退出后的核对与恢复，不让重启后的程序把未完成切换显示成成功。
- 已打开终端仍使用原环境，界面提示重新打开；新命令在切换成功后统一进入目标环境。
- 原环境不自动停止或删除；仍有执行中的任务时保留其执行目标信息，不能用新绑定取消旧任务。
- Nginx 重载期间旧请求可能在原环境完成，不宣称所有请求在同一时刻原子迁移。

## 6. 定时任务方案

- 共享模式使用环境容器内的 Cron 调度绑定项目，取消每项目一个 PHP Cron 容器的做法。
- 环境启动脚本负责 PHP-FPM 与 Cron 的启动、退出及信号处理，检查两者状态；调度不依赖桌面应用保持运行，不挂载 Docker socket。
- 每个项目保留自己的任务定义、日志和状态；环境汇总生成调度表，修改一个项目不能覆盖其他项目任务。
- 任务使用项目真实绝对路径，运行前核对项目绑定和启停状态。过时的旧环境调度记录必须跳过执行。
- 沿用任务文件锁，确保切换时新旧环境不会并发运行同一任务；运行记录增加环境 ID、容器 ID 与执行标识。
- 切换后新任务使用目标环境，原环境中已开始的任务继续完成，取消操作依据执行记录定位。
- 停止项目取消后续调度，不杀死正在执行的任务；环境停止/重建时展示活动任务并要求先处理。
- 自动调度、手动执行、任务移动、删除、取消、日志清理均需覆盖共享与独立运行模式。

## 7. 旧项目迁移

- 先支持 PHPBox 生成且能明确识别的项目；自定义多阶段 Dockerfile、额外挂载、特殊系统依赖等无法可靠转换时列出原因，保留原运行方式。
- 迁移向导展示原 PHP、扩展、配置、代码路径和数据库连接变化，让用户选择已有环境或据此创建新环境。
- 旧的自动生成扩展版本限制列入调整清单；用户明确固定的版本不能静默覆盖。
- 不自动复制旧 PHP 配置到已经有人使用的共享环境；需要原配置时创建独立的同版本环境。
- 保存原 Compose、Dockerfile、PHP/Nginx 配置快照及镜像身份；保留项目 Compose 名称和数据卷身份。
- 为项目写入受管理的共享模式配置，移除其 PHP/Cron 服务引用，按需调整并重新创建该项目 Nginx。这是首次迁移成本，后续环境切换仅重载配置。
- 旧任务正在运行时等待其结束再完成独立模式迁移，避免移除旧 Cron 容器中断任务。
- 验证成功后停止旧 PHP/Cron 容器，保留回退资料；失败恢复原配置与原运行状态，不执行带 volumes 的整体清理。
- 已安装 PHP 扩展若未写入 Dockerfile，也纳入迁移盘点；停止项目无法探测的内容明确标注未知。
- 迁移时原代码、数据库和应用依赖不执行升级或清理。

## 9. 验收清单

- 两个项目共享一个 PHP 环境：网站与 pbox php / composer / exec / shell 均进入各自目录，互不串项目。
- 相同 PHP 版本不同配置的两个环境可以同时运行和选择；展示实际版本及配置。
- 切换到不同 PHP 版本及同版本不同配置的环境；源/目标 PHP 容器不被重建，其他项目持续可用。
- 项目拥有各自 MySQL/Redis 时连接正确实例；重复服务名不串库，已有数据库数据保持不变。
- 运行、停止、异常、构建中的环境及停止项目有明确处理；项目删除/停止不销毁共享环境。
- Composer 要求与目标环境不符时仍可切换，依赖文件保持不变；目标不可达、Nginx 检查失败、重载失败、调度写入失败时恢复原状态。
- 切换中取消、退出应用或进程异常终止后可识别未完成操作；并发命令不能绕过操作互斥。
- 任务切换不重复执行；旧任务继续运行且可以正确取消；应用退出、Docker 重启后调度恢复正确。
- 新建或重命名项目后路径、任务、日志和数据库别名正确；不因新增项目重建所有环境。
- 代理变量不会重新被 Docker 客户端注入为容器 localhost；共享环境配置修改不覆盖应用自己的 .env。
- 标准旧项目迁移成功及失败回退；自定义项目不被静默重写；旧镜像、数据和配置身份可核对。
- 重用现有 Python 3.8/3.14 与 offscreen/xcb/wayland CI；增加独立的真实 Docker 集成验收，不能仅凭 mock 测试判断通过。
- 编译产物验证 phpbox/pbox、单实例启动、后台操作窗口恢复、退出和重新进入后的环境绑定。

第一版不包含：自动升级 Composer 依赖、强制迁移所有旧项目、按项目划分 FPM pool、透明全流量代理、多租户隔离、自动清理仍被引用的环境。
